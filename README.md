# BZ Plate Studio

BZ-X シリーズの蛍光顕微鏡で撮影したウェルプレート画像を Mac / Windows で扱う
ソフトウェアです。メーカー純正ソフトも USB ドングルも要りません。

- **`.ktf`（貼り合わせ済みモザイク）を開いて表示・書き出す**
- **生の各視野タイルから自前で貼り合わせる（スティッチング）**

> 装置メーカーとは無関係の、有志による独立したプロジェクトです。利用者が自分で
> 取得したデータを自分で開くための相互運用を目的としています。本文中の製品名は
> 各権利者の商標です。

**対象は「ウェルプレート撮影」です。** ウェルごとにフォルダがあり、その下が
`X###Y###`（視野位置）に分かれている撮影を扱います。組織切片などの XY スキャン
（`XY01/` の下にタイルが連番で並ぶ形式）には対応していません。

## できること

- **ウェルプレート表示** — 実験フォルダを開くとウェルがサムネイル付きで並びます。
  フォルダはどの階層を選んでも構いません（1 実験でも、実験を束ねた親でも、HDD の
  ルートでも自動で探します）。
- **マルチチャンネル疑似カラー** — チャンネルごとに色・min/max・ガンマ・Solo
  （単一チャンネルをグレースケール表示）。
- **拡大時のフル解像度表示** — 表示中の領域だけをディスクから原寸で読み直すので、
  巨大なファイル（500 MB 超）でも全体を読み込まずに細部が見えます。
- **実寸スケールバー** — メタデータの µm/px から算出し、画像の左下に表示。ズームに
  追従します。倍率は左下の欄に直接入力できます。
- **カーソル読み取り** — 画素座標、ステージ絶対座標（µm）、各チャンネルの生強度。
- **メタデータ表示** — レンズ、NA、作動距離、視野、露光、ビニング、観察モード。
- **サンプル条件の表** — ウェルごとの条件を Excel から直接貼り付けられます。列名の
  変更・列の追加/削除ができ、実験ごとに自動保存されます。
- **書き出し** — 表示画像（PNG）、チャンネル別のフル解像度 TIFF、プレート全体を
  1 つの PDF（画質を 5 段階から選択、各ウェルにサンプル条件を自動で記入）。
- **スティッチング** — 生タイルから自前でモザイクを再構成（下記）。

## インストールと起動

### 方法 A: ビルド済みアプリ（推奨）

[Releases](../../releases) から自分の環境に合うものを取得してください。

- **macOS** — `BZ-Plate-Studio-macOS-appleSilicon.zip`（M1/M2/M3…）または
  `BZ-Plate-Studio-macOS-intel.zip`。展開して `BZ Plate Studio.app` を Applications へ。
  初回のみ **右クリック → 開く**（署名していないため Gatekeeper が一度警告します）。
  それでも開けない場合はターミナルで一度だけ:
  `xattr -cr "/Applications/BZ Plate Studio.app"`
- **Windows** — `BZ-Plate-Studio-Windows.zip` を展開して `BZ Plate Studio.exe`。
  SmartScreen が出たら「詳細情報 → 実行」。

### 方法 B: ソースから（Python 3.9 以上）

```bash
pip install -r requirements.txt
python main.py
```

起動すると **「.ktf から始める」「生画像から始める」** の選択画面が出ます。
`.ktf` は貼り合わせ済みモザイクの表示、生画像は各視野のタイルからの
スティッチングです。あとから **File ▸ Choose Workflow…** で切り替えられます。
前回開いたフォルダはワークフローごとに記憶されます。

**操作** — スクロール／ピンチ＝ズーム・ドラッグ＝移動・`Ctrl/Cmd+0`＝全体表示・
`Ctrl/Cmd+1`＝100%・`Ctrl/Cmd+Shift+A`＝自動コントラスト。

## スティッチング（生タイルからの貼り合わせ）

Export 欄の **Stitch Raw Tiles…** から実行します。装置が書き出した各視野の
OME-TIFF（`<実験>/<ウェル>/X###Y###/`）を読み、モザイクを再構成します。

- タイルの位置は**画像そのものから測定**します（重なり帯の位相相関）。1 ウェルにつき
  幾何を 1 回だけ測り、全チャンネル・全 Z スライスで使い回すので、**チャンネル間の
  位置ずれが生じません**。
- **照明ムラ補正（フラットフィールド）** をチャンネルごとに行い、**保存される画素に**
  適用できます。**既定はオフ**（撮影されたままの値を保存）です。同じ明るさの標本でも
  視野内の位置だけで ±40 階調ずれるため、**ウェル間や視野間で強度を比較するときは
  オンに**してください。
- 自分の幾何を測れないウェル（標本が疎・空）は、**同じプレートの他ウェルの値を継承**
  します（タイルを密着させて標本を二重計上することはしません）。
- 物理的にありえない重なりや、周期的な標本で曖昧になった候補は**採用せず棄却**します。
- Z スタックは最大値／平均／中央スライスの投影を選べます。
- 出力形式は選べます：**マルチチャンネル OME-TIFF**（チャンネル名と画素サイズを保持。
  Fiji / QuPath / napari でそのまま開けます）、PNG 合成画像、チャンネル別 TIFF、
  **PDF**（1 ウェル 1 ページ／プレート全体を 1 枚のコンタクトシート／
  コンタクトシート＋各ウェル 1 ページを 1 つの PDF にまとめたもの）。
  PDF には Conditions タブに入力したサンプル条件が各ウェルに記入されます。
- **Conditions（サンプル条件）は生画像モードでも使えます**。実験ごとに保存され、
  `.ktf` モードとは独立です。
- 実行ごとに **`stitch_qc.csv`** を書き出します（後述）。

### 定量に使う前に知っておくこと

敵対的レビュー（`review_2026-08-05/` に全レポート）で確認された限界です。

- `lattice_residual_*` は**内部整合性であって精度ではありません**。幾何を求めたのと
  同じ推定器で計算しているため、すべての継ぎ目が同じ誤った特徴（センサー上のゴミ等）
  に揃うと、残差は小さいまま配置だけが誤ります。独立した指標は
  **`step_deviation_vs_plate`**（他ウェルとの比較）で、残差が完璧でもこの値が大きい
  ウェルは要確認です。
- 照明ムラ補正は**標本がタイル間で動くこと**を前提にします。実測した境界は「各視野の
  約 40% 以上が新しい内容であれば分離できる」で、この装置のタイリングは約 71% な
  ので安全側です。カメラ座標に固定されたもの（センサーのゴミ、反射）は原理的に照明ムラと
  区別できず、除去されます。ウェルごとの判定は `shading_identifiable` 列に出ます。
- タイルは**整数座標**に配置します。サブピクセル精密化は QC の数値には使いますが配置
  には使っていません。実機での残差は約 1 px（最大 3 px）で、全体像の観察には十分、
  点状シグナルの 1 細胞計測には注意が必要です。
- 重なり部は**フェザーブレンド**（2 回の露光の平均）です。厳密な強度定量には、
  チャンネル別 TIFF と単一タイル領域を使うか、継ぎ目の画素を別扱いにしてください。

## ビルド

各 OS 用のビルドは `v*` タグを押すと GitHub Actions が自動で作ります
（`.github/workflows/build.yml`）。手元でビルドする場合:

```bash
python -m venv .buildenv && source .buildenv/bin/activate   # Windows: .buildenv\Scripts\activate
pip install -r requirements.txt pyinstaller
pyinstaller --noconfirm ktf_viewer.spec
```

> **conda / Anaconda の base 環境ではビルドしないでください。** Anaconda が同梱する
> Qt 5 を PyInstaller が一緒に取り込み、起動時に
> *"uses incompatible Qt library (5.15.0)"* で落ちるアプリができます。pip だけを
> 入れたクリーンな venv を使ってください（CI はそうしています）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `ktf_reader.py` | `.ktf` の解析（ヘッダ、タイル索引、mmap による全体/部分再構成、XML メタデータ） |
| `stitcher.py` | 生 OME-TIFF タイルからのモザイク再構成（Qt 非依存） |
| `render.py` | 合成とスケールバーの計算（純関数、Qt 非依存） |
| `main.py` | PyQt6 の GUI |
| `version.py` | バージョン定数（唯一の正） |
| `tests/make_well.py` | 真値つき合成タイルの生成（実データなしで検証するため） |
| `make_synthetic.py` | 形式互換の合成 `.ktf` を生成 |

## `.ktf` 形式（KTL2 / BZ03）

- **ヘッダ**（112 バイト）— magic `KTL2`、フッタ位置、ファイルサイズ、画像寸法、
  タイルサイズ（512）。
- **データ部** — 生の `uint8` タイル。1 面 512×512（明視野は 1 面、蛍光は 3 面）。
- **フッタ** — タイル索引。`(uint64 offset, uint64 size)` の並び（行優先）。
- 続いて **JPEG サムネイル**、**XML メタデータ**。
- XML の `System.Double` は **int64 のビットパターン**で格納されています
  （例: キャリブレーション `4656510908468559872` → `2000.0` nm/px = 2.0 µm/px）。
  `ktf_reader.decode_packed_double` を参照。

## バージョン

`version.py` の `__version__` が唯一の正です。セマンティックバージョニング
（MAJOR.MINOR.PATCH）で、MAJOR は出力形式や `.ktf` の読み取りに互換性のない変更、
**通常の更新は末尾（PATCH）を上げます** — 修正も小さな改善もここです。MINOR は
まとまった新機能、MAJOR は出力形式や `.ktf` の読み取りに互換性のない変更のときだけ。
現在 **1.4.3**。

**アップデート通知** — 起動時に GitHub の最新リリースを確認し、新しい版があるときだけ
知らせます（オフラインや確認失敗のときは何も表示しません）。**Help ▸ アップデートを
確認…** でいつでも手動確認でき、**Help ▸ 起動時にアップデートを確認** で自動確認を
オフにできます。
